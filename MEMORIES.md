## ⛔ HARD WRITING RULE — NO MID-SENTENCE COLONS (do not violate, ever)

Uriah has flagged this 4-5 times and is rightly fed up. **Never use a colon mid-sentence** before a single explanatory word, clause, or example, in ANYTHING — SOQ, STD 678, resume, cover letter, AND chat messages to him. A colon may ONLY introduce a real list or formatted series. If you are about to write "X: Y" where Y explains or expands X, STOP and rewrite with a period or comma. Example of the violation he hates: "I administer Active Directory directly: creating users and groups." Fix: "I administer Active Directory directly. I create users and groups." Before sending any draft or message, scan every colon and confirm each one introduces a list, not an explanation. This is a zero-tolerance item.

**SOQ is stricter still (settled 2026-06-21): an SOQ contains ZERO colons of any kind**, not even a list-introducing one, because SOQ answers flow as one paragraph with no formatted lists for a colon to introduce. The only exception is a true numeric colon (a clock time like 7:00, a ratio like 3:1). This does NOT extend to the resume, which keeps its label-colons (skills rows, project headers), or to the STD 678. The `tools/verify_doc.py` pre-submit gate enforces the SOQ zero-colon rule and no longer runs the colon check on resumes. One known edge: if a posting's SOQ question text itself contains a colon and you restate the question verbatim (required), the gate will flag that colon. That is an expected false positive on the agency's own wording. Keep the verbatim question and override the flag.

## Resume best practices (research-backed 2026) — default checklist for every resume draft

External standards confirmed by web research 2026-06-22 (BeamJobs, Resume Worded, Resume.io, Extern, ResumeAdapter). Use as the default checklist when drafting or tailoring any resume. These complement the house-style and honesty rules, they do not replace them.

- **One page.** Correct for Uriah (recent grad, under ~10 years experience). Two pages only justified at 10+ years. If a draft spills onto a second page, fix it with fewer/shorter bullets, never by adding a page.
- **3 to 5 bullets per job, each 1 line, 2 lines max.** The biggest lever. Long multi-line bullets make a recruiter skim faster, not slower (first pass is ~6 seconds). If a bullet runs 3+ lines, cut it. This is the exact issue behind the "too dense" feedback on the older drafts, and the research backs it.
- **Lead every bullet with a strong action verb, and quantify it.** Real numbers only, never invented (see the quantify-everything note). Don't leave a role or project with zero metrics when an honest one exists. Example fix from this session: the scraper bullet lost its "60+ postings" count when tightened, which is the one project left with no number.
- **15 to 25 keywords matched to the target posting,** woven through the summary, skills rows, and bullets so both the applicant tracking system (ATS) and the human screener match. This is WHY the dense keyword-rich skills block is an asset, not bloat. Mirror the posting's exact tool and platform names.
- **Skills section lists concrete tools** (operating systems, software, hardware, platforms) plus certs. Uriah's four-row skills block already does this well.
- **Summary: 2 to 3 lines, action verbs and keywords, no fluff.** Keep education and certs out of it (they have their own section, per the no-certs-in-summary note).
- **Skimmability beats density.** When unsure, favor the lighter layout (shorter sentences, acronyms only per the resume acronyms-only rule above, slight line spacing for air) over packing lines edge to edge.

How this applies to Uriah specifically: his CONTENT is already above the median entry-level IT resume (degree, four CompTIA certs, a metrics-backed internship, strong projects), so resume polish has largely hit diminishing returns. The two levers that still matter are short/quantified bullets and TARGETING. Maintain two cuts, a security/cloud-weighted one and a support-weighted one, and aim the right one at each posting (see the ITA-support-lane triage note). The binding constraint on callbacks is experience depth and role fit, not formatting.
