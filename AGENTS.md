# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this project is

This is not a codebase. It is Uriah Raffer's working folder for applying to California state IT jobs through CalCareers. The work here is producing application materials: tailored resumes, Statements of Qualifications (SOQs), and STD 678 application content for specific job postings.

## Folder structure and conventions

- Each job application gets its own folder named `JC-###### (Job Title)/`, containing the job posting PDF, the duty statement PDF, and the tailored deliverables for that posting.
- Deliverables are named `Uriah_Raffer_<Doc>_JC-######` (e.g., `Uriah_Raffer_Resume_JC-520957.docx`). Produce both .docx and .pdf versions.
- Root-level files are shared source material reused across applications.

## Key reference files — read before drafting anything

- `soq-writing-guide.md` — **Required reading before writing any SOQ, resume content, or other prose submitted under Uriah's name.** Defines his target voice (plain, direct, concrete, first person), the anti-AI checklist every draft must pass, the STAR structure for SOQ answers, and the working process: Codex asks targeted questions to pull real specifics from Uriah, then drafts; never invent specifics.
- `Employment_History_STD678.md` — Canonical, pre-approved employment history blocks for the CalCareers STD 678 form, each under the 1,500-character field limit, with no em dashes and no mid-sentence colons. Use these as the source of truth for job duties wording. Note the field notes at the bottom (Log(N) Pacific verification contact, the approved brute-force bullet wording, the employment-gap explanation).
- `Uriah_Raffer_IT_Support_Resume.pdf` — Base resume to tailor from for each posting.
- `Transcript_UriahRaffer.pdf` — WGU transcript (B.S. Network Engineering and Security, conferred Oct 2025).
- `CA_State_Hiring_Field_Guide.docx` — Background on how CA state hiring works (exams, eligibility, SOQs, the STD 678).

## Working rules

1. **New application:** create the `JC-###### (Title)/` folder, save the posting and duty statement PDFs into it, then tailor the resume and SOQ against the duty statement and the SOQ prompt in the posting.
2. **SOQ workflow:** follow the process in `soq-writing-guide.md` — get the actual prompt and page/word limit, ask Uriah for the real specifics (situation, tools, numbers, outcome), draft with STAR, then check the draft against the anti-AI checklist before calling it done.
3. **Never fabricate experience.** Everything must trace back to `Employment_History_STD678.md`, the base resume, or facts Uriah supplies in conversation. Self-employment (options trading, online business) was deliberately removed from applications — do not reintroduce it.
4. **Formatting constraints for CalCareers fields:** under 1,500 characters per Duties Performed block, no em dashes, no mid-sentence colons.
5. SOQs typically must follow the exact format the posting demands (page limit, font, numbered responses to each prompt) — check the posting's SOQ instructions every time; failure to follow them disqualifies the application.
